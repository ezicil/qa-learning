### HTTP,  клиент-сервер, запросы.
HTTP - Протокол для получения ресурсов, например HTML-документов. Hypertext Transfer Protocol. Клиент - сущность, инициирующая запрос на сервер. Сервер - сущность которая обслуживает запросы клиента. Клиент общается с сервером отдельными сообщениями, которые называются запросами (requests). Сообщения от сервера к клиенту называются ответами (response).
Схема.

Client ---> Proxy ---> Proxy ---> Server.

Client <--- Proxy <--- Proxy <--- Server.

Между клиентом и сервером как правило существуют многочисленные посредники, называемые Proxy, которые выполняют различные функции, например кэширование.
User agent - это любой инструмент или устройство действующие от лица пользователя. Эту задачу обычно выполняет веб-браузер, но так же могут и программы, которые используются например для отладки.
Что бы отобразить веб-страницу, браузер отправляет вначале первичный запрос на сервер, что бы получить HTML-документ. Затем браузер поочередно отсылает запросы на сервер на получение дополнительного контента (скрипты, стили, видео, изображения и т.п.). Далее браузер собирает все эти данные в единую страницу для отображения пользователю. В дальнейшем браузер может догружать необходимые ресурсы и обновлять страницу у пользователя.
С другой стороны находится сервер, который обслуживает запросы браузера (клиента). Обычно сервер представляют как одну некую виртуальную машину, но на самом деле это может быть и группа серверов, между которыми балансируется нагрузка по запросам. 
#### Основные аспекты HTTP
1. HTTP является простым. Сообщения могут быть прочитаны и поняты людьми.
2. HTTP является расширяемым. Новая функциональность может быть добавлена простым соглашением между клиентом и сервером о семантике нового заголовка.
3. HTTP не имеет состояния, но имеет сессию (куки).
4. Для реализации HTTP необходим любой надежный транспортный протокол. Обычно это TCP.
#### HTTP-поток.
Когда клиент хочет взаимодействовать с сервером, он выполняет следующие шаги:
1. Открытие TCP соединения.
2. Отправка HTTP-сообщения (запроса).
3. Чтение ответа от сервера.
4. Закрытие или переиспользование соединения для последующих запросов.
#### Запросы
Пример запроса: GET / HTTP/1.1 
Host: developer.mozilla.org
Accept-Language: fr
Body: ...
Где:
- `GET` - HTTP-метод запроса
- `/` - путь к ресурсу
- `HTTP/1.1` - версия HTTP протокола
- Заголовки (Headers)
- `Body` - тело запроса, в котором передаются данные на сервер.
#### Ответы
Пример ответа: HTTP/1.1 200 OK
date: Tue, 18 Jun 2024 10:03:55 GMT
cache-control: public, max-age=3600
Body: ...
Где:
- `HTTP/1.1` - версия HTTP протокола
- `200` - статус-код ответа
- `OK` - сообщение состояния
- HTTP-заголовки
- `Body` - тело ответа, обычно данные которые сервер отправил обратно клиенту.

#### Что происходит когда ты переходишь на сайт?
Когда переходишь на сайт, браузер выстраивает такую цепочку:
1. URL: `http://test.site.org/main.html`
	- `http` - протокол 
	- `test.site.org` - домен
	- `/main.html` - путь до HTML-документа.

2. DNS (Domain Name System) - система доменных имен, позволяет связать домен и ip-адрес сервера. 
3. TCP-соединение. Браузер устанавливает tcp соединение по полученному ip.
4. HTTP-запрос. Браузер отправляет запрос на сервер для получения HTML-страницы.
5. HTTP-ответ. Сервер возвращает запрошенную страницу, заголовки и статус-код.
6. Браузер собирает все полученное в единую страницу сайта для отображения пользователю.
