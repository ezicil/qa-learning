# Postman-коллекции: JSONPlaceholder и RestfulBooker
Учебные коллекции Postman для практики тестирования REST API: ручные запросы, автоматические проверки на JavaScript (`pm.test`), цепочки запросов и негативные сценарии.
## Что внутри


| Файл | Запросов | Автопроверки | Описание 
|---|---|---|---|
| `JSONPlaceholder.postman_collection.json` | 5 | нет | Базовые запросы CRUD к фейковому API: GET (список и один пост), POST, PUT, DELETE |
| `RestfulBooker.postman_collection.json` | 14 | да, у каждого запроса | Полный цикл работы с бронированиями: авторизация, создание, чтение, обновление, удаление, а также негативные проверки |

  

Тестируемые сервисы:

- https://jsonplaceholder.typicode.com: фейковый API (данные на сервере не сохраняются);

- https://restful-booker.herokuapp.com: учебный сервис бронирования отелей (документация на главной странице сайта).

  

## Как импортировать
  

1. Открыть Postman.

2. Нажать **Import**.

3. Выбрать файлы для импорта.

4. В левой панели появятся коллекции.

  

Адрес сервиса задан переменной коллекции `baseUrl` (вкладка **Variables** у коллекции). Менять её не нужно.

  

## Как запустить

  

**Запрос:** открыть запрос и нажми **Send**. Результаты проверок видны на вкладке **Test Results**.

  

**Всю коллекцию:**

1. Нажать на три точки рядом с коллекцией, затем **Run collection**.

2. Нажать **Run**.

3. Итоговый отчёт покажет, сколько проверок пройдено и какие упали.

  

## Порядок запросов и зависимости (RestfulBooker)

  

Запросы связаны через переменные коллекции, поэтому **порядок важен**:

  

| Переменная | Где записывается | Где используется 
|---|---|---|
| `token` | `Auth` | запросы с изменением и удалением брони |
| `bookingID` | `CreateBooking` | запросы чтения, обновления и удаления брони |

  

Порядок запросов:

  

| № | Запрос | Метод | Что проверяет | Ожидаемый код 
|---|---|---|---|---|
| 1 | Auth | POST `/auth` | вход с верными данными, токен сохраняется | 200 |
| 2 | Auth wrong | POST `/auth` | вход с неверными данными: токена нет, `reason` равно `Bad credentials` | 200 |
| 3 | GetBookingIds | GET `/booking` | список броней непустой | 200 |
| 4 | CreateBooking | POST `/booking` | бронь создана, `bookingID` сохраняется | 200 |
| 5 | GetBooking | GET `/booking/{id}` | данные брони совпадают с отправленными | 200 |
| 6 | GetBooking with wrong id | GET `/booking/{id}` | несуществующий id | 404 |
| 7 | UpdateBooking | PUT `/booking/{id}` | полное обновление с токеном | 200 |
| 8 | UpdateBooking without token | PUT `/booking/{id}` | обновление без токена | 403 |
| 9 | UpdateBooking without firstname | PUT `/booking/{id}` | тело без обязательного поля | 400 |
| 10 | PartialUpdateBooking | PATCH `/booking/{id}` | изменены только указанные поля | 200 |
| 11 | PartialUpdateBooking without token | PATCH `/booking/{id}` | частичное обновление без токена | 403 |
| 12 | DeleteBooking without token | DELETE `/booking/{id}` | удаление без токена | 403 |
| 13 | DeleteBooking | DELETE `/booking/{id}` | удаление с токеном | 201 |
| 14 | HealthCheck | GET `/ping` | сервис доступен | 201 |


## Негативные проверки


- Запросы «without token» отличаются от основных только отключённым заголовком `Cookie: token={{token}}`.

- Сервис RestfulBooker возвращает нестандартные коды: удаление брони отвечает **201**, неверный пароль при входе отвечает **200** с текстом `reason`. Проверки в коллекции написаны под фактическое поведение, описанное в документации сервиса.

- Ожидаемые результаты негативных проверок основаны на документации и соглашениях REST. Если документация не описывает случай, ожидание считается допущением.

  

## Известные особенности и замечания

  

- JSONPlaceholder фейковый: после POST запись на сервере не появляется (например, GET `/posts/101` вернёт 404). Запросы коллекции показывают формат запросов и ответов, но не проверяют сохранение данных.

## Результат прогона

  

Запуск всей коллекции RestfulBooker через Runner: все проверки пройдены.

  

## Инструменты

  

Postman, JavaScript (`pm.expect`), JSON.
