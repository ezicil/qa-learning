### HTTP-методы

|  `PATCH`  |                  Частичное изменение ресурса.                  |      Да      |           Может           |      Нет      |    Нет     | Только если включена информация о дате последнего изменения |

Метод является идемпотентным если повторный идентичный запрос, сделанный один или несколько раз подряд, имеет один и тот же эффект, не изменяющий состояние сервера.
Метод является безопасным, если он не изменяет состояние сервера.

### Коды ответа
Пять классов кодов ответа:
1. Информационные - 1хх
2. Успешные ответы - 2хх
3. Перенаправление - 3хх
4. Ошибка клиента - 4хх
5. Ошибка сервера - 5хх

### Куки, JWT, сессия.

Cookie - небольшие файлы, которые веб сервер отправляет клиенту для хранения какой-либо информации. Когда клиент впервые посещает сайт, сервер отправляет в браузер клиента куки. Когда клиент посещает сайт в последующие разы, эти куки браузер автоматически включает в заголовки запросов. Это позволяет серверу идентифицировать клиента. В куки нельзя хранить пароли и другую важную информацию.

Сессия - это методика хранения данных о клиенте на сервере. Как правило сервер использует куки как идентификатор для сессии. Куки используются для определения связи между конкретным клиентом и его сессией на сервере.

JWT - JSON Web Token - необходим для передачи информации межу сервером и клиентом в закодированном виде. Состоит из 3х частей, разделенных точкой: xxx.yyy.zzz, где x - заголовок, y - даннные и z - сигнатура. Заголовок - системная информация (алгоритм шифрования, тип токена и т.д.). Данные - какая-либо информация о текущем пользователе (username, роли). Сигнатура - сгенерированная строка, которая проверяет подлинность JWT-токена. Для генерации сигнатуры необходим уникальный секретный ключ, который хранится только на сервере. Сигнатура = Загловок + Данные + Ключ. Каждый JWT-токен имеет срок жизни.  JWT-токены бывают двух видов: Access и Refresh. Access-токен - служит для доступа. Refresh-токен - служит для обновления Access токена. Access-токен чаще всего хранится в LocalStorage в браузере. Refresh-токен хранится в куки с флагом httpOnly. Тут так же не стоит хранить пароли и другую важную информацию.

Когда происходит авторизация в аккаунт:

Клиент ---> данные для входа ---> Сервер (генерация токенов, аутентификация) ---> токены (Refresh ---> Cookie,  Access ---> LocalStorage) ---> Клиент. 
Далее при запросе клиента на сервер, в заголовок будет добавляться access токен. Если полученный токен валидный, то сервер обрабатывает запрос клиента и отправляет свой ответ обратно.
