## Виды тестирования
<img width="307" height="230" alt="image" src="https://github.com/user-attachments/assets/c203b02c-8600-4fe7-a120-769beca10929" />

Снизу вверх по степени важности.
Unit-тестирование - проводится разработчиками на этапе разработки.
Интеграционное тестирование - тестирование взаимодействия различных частей приложения
Системное тестирование - тестирование всего приложения как единой системы
UI тесты - проверка пользовательского интерфейса
### Виды тестирования
1. По запуску кода на исполнение:
- Статическое
- Динамическое
2. По доступу к коду:
- Метод белого ящика (есть доступ)
- Метод черного ящика (нет доступа)
- Метод серого ящика (есть доступ к отдельным частям)
3. По степени автоматизации:
- Ручное тестирование
- Автоматизированное тестирование
4. По уровню детализации:
- Модульное тестирование - отдельные небольшие части
- Интеграционное тестирование - взаимодействие между частями
- Системное тестирование - приложение как единое целое
5. По степени важности тестируемых функций (по убыванию):
- Smoke-тестирование - тестирование ключевой функциональности
- Тестирование критического пути - тестирование повседневной функциональности
- Расширенное тестирование - тестирование всей функциональности
6. По принципам работы с приложением: 
- Позитивное тестирование 
- Негативное тестирование

Это упрощенная классификация.


| Вид           | Определение                                                                                            | Пример                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Smoke         | Проверка основного (критического) функционала приложения                                               | Проверка возможности сделать заказ в интернет-магазине                                                |
| Sanity        | Быстрая проверка работоспособности внесенного изменения                                                | Проверка новой функции сортировки в интернет-магазине                                                 |
| Регрессионное | Проверка ранее рабочего функционала после внесения изменений с целью убедиться что ничего не сломалось | Проверка функций сортировки, покупки, услуги доставки при добавлении новой функции скидочных купонов. |
| Ретест        | Повторная проверка того, что ранее вызывало баг, с целью убедиться что баг исправлен.                  | Проверка функции сортировки после исправления, которая раньше сортировала в случайном порядке.        |
